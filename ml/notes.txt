RESUME MATCHING ENGINE NOTES
============================

Purpose
-------
The ML folder contains a lightweight resume-to-job-description matching engine.
It compares resume text with a job description and returns a score from 0 to 100.
The implementation is in matching_engine.py. The known skill vocabulary and
aliases are stored in skills_database.py.

The final score is calculated as:

    final_score = keyword_score * 0.40
                + skill_score   * 0.40
                + tfidf_score   * 0.20

All component scores and the final score are percentages from 0 to 100.


FILE: skills_database.py
------------------------

SKILLS
~~~~~~
SKILLS is a Python set containing the canonical skills that the engine can
recognize. Examples include:

- Programming languages: python, java, javascript, typescript, c++, c#, sql
- Frontend: html, css, react, angular, vue
- Backend: node.js, django, flask, fastapi, spring
- Cloud and infrastructure: docker, kubernetes, aws, azure, gcp, linux
- Databases: postgresql, mysql, mongodb, redis
- Data and AI: pandas, numpy, scikit-learn, tensorflow, pytorch, machine
  learning, deep learning, natural language processing, data science
- Other technologies and methods: rest api, graphql, git, agile, scrum

A set is used so that each skill is counted once, even if it appears many times
in the same document.

SKILL_ALIASES
~~~~~~~~~~~~~
SKILL_ALIASES maps common shorthand to one canonical skill name. Examples:

    js       -> javascript
    ts       -> typescript
    nodejs   -> node.js
    postgres -> postgresql
    k8s      -> kubernetes
    ml       -> machine learning
    nlp      -> natural language processing
    rest     -> rest api

This means that a resume mentioning "JS" can match a job asking for
"JavaScript".


FILE: matching_engine.py
------------------------

Imports
~~~~~~~

    import re

The re module is used for case-insensitive text cleanup and boundary-aware
regular-expression searches.

    import math

The math module supplies square root for the fallback cosine-similarity
calculation.

    from collections import Counter

Counter counts how many times each token occurs in each text.

    from skills_database import SKILL_ALIASES, SKILLS

The matching engine reuses the central skill vocabulary instead of maintaining
a second copy of the list.


_TOKEN_PATTERN
~~~~~~~~~~~~~~

    _TOKEN_PATTERN = re.compile(r"[a-z0-9+#.-]+")

This pattern finds words, numbers, and technology names such as c++, c#,
node.js, and scikit-learn. It is used by _tokens for keyword matching.


_STOP_WORDS
~~~~~~~~~~~
This set contains common words such as "the", "and", "to", and "with".
These words usually do not represent useful matching keywords, so they are
removed before keyword comparison and fallback cosine comparison.


_text(value)
~~~~~~~~~~~~

    def _text(value):
        return value if isinstance(value, str) else ""

This helper prevents errors when a caller passes None or another non-string
value. Non-string input is treated as empty text.


_tokens(text)
~~~~~~~~~~~~~

    def _tokens(text):
        return [token for token in ... if token not in _STOP_WORDS]

The function:

1. Converts input to a safe string using _text.
2. Converts text to lowercase.
3. Extracts tokens with _TOKEN_PATTERN.
4. Removes stop words.

It returns a list. The list is later converted to a set for keyword matching or
counted for cosine similarity.


calculate_match(resume_text, job_description)
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
This is the main public function.

It calls:

    keyword_match(resume_text, job_description)
    skill_match(resume_text, job_description)
    tfidf_match(resume_text, job_description)

The results are weighted 40%, 40%, and 20%, respectively. The result is
rounded to two decimal places and returned as a float.

Example:

    score = calculate_match(
        "Python developer with Docker and SQL",
        "Looking for Python, Docker, and SQL"
    )

A higher score means the resume has more overlap with the job description.
The score is not a hiring decision; it is only an automated similarity signal.


keyword_match(resume_text, job_text)
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
This function measures overlap between general keywords.

Important operations:

    job_tokens = set(_tokens(job_text))
    resume_tokens = set(_tokens(resume_text))

Sets remove duplicate occurrences, so repeating a keyword does not inflate the
score.

The intersection is calculated with:

    job_tokens & resume_tokens

The score is:

    number of matching job keywords / number of job keywords * 100

If the job description has no usable keywords, the function returns 0.0 rather
than dividing by zero.

This score is directional: it asks how much of the job's vocabulary appears in
the resume. Extra resume words do not reduce the score.


skill_match(resume_text, job_text)
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
This function focuses only on recognized technical and professional skills.

It extracts skills from both documents. The requested skills are the skills
found in the job description. The score is:

    matching requested skills / requested skills * 100

For example, if a job asks for Python, Docker, and SQL and the resume contains
Python and SQL, the skill score is 66.67.

If the job description contains no recognized skills, the function returns 0.0.
This avoids treating an unrecognized job description as a perfect match.


extract_skills(text)
~~~~~~~~~~~~~~~~~~~~~
This function returns a set of canonical skill names found in text.

Processing steps:

1. Convert the input to a safe string.
2. Convert it to lowercase.
3. Replace characters outside letters, numbers, plus, hash, dot, and hyphen
   with spaces.
4. Search for every canonical skill in SKILLS.
5. Search for every alias in SKILL_ALIASES.
6. Add the canonical name for every matching alias.

The regular expression uses boundaries so that short skills do not accidentally
match inside larger words. For example, "java" should not match the word
"javascript".

The returned value is a set, so repeated mentions are only counted once.
Matching is case-insensitive.


 tfidf_match(resume_text, job_text)
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
This function measures overall text similarity using TF-IDF and cosine
similarity.

If either input is empty after trimming whitespace, it returns 0.0.

Normally it imports scikit-learn lazily and performs these operations:

1. TfidfVectorizer converts the two documents into weighted word vectors.
2. cosine_similarity compares the resume vector with the job vector.
3. The result from 0.0 to 1.0 is multiplied by 100.

The import is inside the function so that keyword and skill functions can still
be imported and used when scikit-learn's native dependencies are unavailable.

The code catches ImportError, OSError, and ValueError. If scikit-learn cannot
run, it uses _token_cosine instead of crashing.


_token_cosine(left_tokens, right_tokens)
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
This is the dependency-free fallback for tfidf_match.

It:

1. Counts token frequencies with Counter.
2. Creates a vocabulary containing tokens from both documents.
3. Calculates each vector's length using the square-root sum of squared counts.
4. Calculates the dot product between the two vectors.
5. Returns:

       dot_product / (left_length * right_length)

If either vector has no usable tokens, it returns 0.0.

This fallback is a count-based cosine similarity, not a full TF-IDF
implementation, but it preserves the same 0-to-100 score contract when the
optional scientific Python stack cannot load.


tfidf_similarity(resume_text, job_text)
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
This is a compatibility wrapper. It calls tfidf_match directly. Code written
against the original function name can continue to work without changes.


Typical usage
-------------
Run from the ml directory:

    from matching_engine import calculate_match

    resume = "Python developer experienced with Docker, SQL, and AWS"
    job = "We need a Python developer with Docker and SQL"
    score = calculate_match(resume, job)
    print(score)

The result is a numeric percentage. A score of 0 means no measurable overlap;
a score of 100 means the component calculations found complete overlap.


Edge cases and behavior
-----------------------
- Empty resume or job text returns zero for the affected comparison.
- None and other non-string values are treated as empty text.
- Repeated words and repeated skills are counted once for overlap scores.
- Skill aliases are normalized to canonical names.
- Scores are rounded to two decimal places.
- The final score uses keyword, skill, and text-similarity evidence together.
- scikit-learn is preferred when available; the standard-library fallback keeps
  basic matching operational when its binary dependencies cannot load.


Dependencies

requirements.txt lists numpy, scipy, scikit-learn, pandas, and matplotlib.
Only scikit-learn is needed by the preferred TF-IDF path. The keyword, skill,
and fallback cosine paths use Python's standard library.

TEST_MATCHING
-------------
The file test_matching.py contains automated tests for matching_engine.py.
It can be used with pytest, or run directly with Python because it also has a
manual test runner at the bottom of the file.

Imports
~~~~~~~
The test file imports the public matching functions:

    calculate_match
    keyword_match
    skill_match
    tfidf_match
    extract_skills

The fallback test additionally imports the private helpers _token_cosine and
_tokens so the dependency-free similarity implementation is checked directly.

Test functions
~~~~~~~~~~~~~~

test_perfect_match
~~~~~~~~~~~~~~~~~~
Uses the same text as both the resume and job description. It checks that a
completely identical document receives a score of at least 90 percent.

test_high_match
~~~~~~~~~~~~~~~
Uses a resume and job description with substantial overlap in Python,
JavaScript, Django, React, REST APIs, AWS, Docker, and PostgreSQL. It expects a
strong score between 70 and 95 percent.

test_medium_match
~~~~~~~~~~~~~~~~~
Compares a JavaScript/React/Node.js/MongoDB resume with a Python/Django/
PostgreSQL/Redis job. Only limited overlap is expected, so the score must be
between 20 and 60 percent.

test_low_match
~~~~~~~~~~~~~~
Compares a graphic-design resume with a DevOps job. Since the skill sets are
unrelated, the score must be 30 percent or lower.

test_skill_extraction
~~~~~~~~~~~~~~~~~~~~~
Checks that aliases are converted into canonical names. The input includes:

    ReactJS -> react
    NodeJS  -> node.js
    Postgres -> postgresql
    K8s     -> kubernetes
    ML      -> machine learning

It also verifies that Python is found directly.

test_keyword_matching
~~~~~~~~~~~~~~~~~~~~~~
Checks general keyword overlap for a resume containing Python, Django, and
Flask against a job asking for those same terms. The expected score is at least
75 percent.

test_skill_matching
~~~~~~~~~~~~~~~~~~~
Checks skill-only matching. The resume contains Python, React, Docker, and
MySQL. The job requests Python, React, AWS, and PostgreSQL. Two of four
requested skills match, so the expected score is approximately 50 percent.

test_tfidf_matching
~~~~~~~~~~~~~~~~~~~
Checks that similar text about an experienced software engineer and Python
produces a TF-IDF score of at least 50 percent.

test_edge_cases
~~~~~~~~~~~~~~~
Checks that empty resume text, empty job text, both empty values, and None
inputs all return exactly 0.0 instead of raising an exception.

test_fallback_cosine
~~~~~~~~~~~~~~~~~~~~
Calls the dependency-free _token_cosine helper directly. Similar token lists
must produce a similarity between 0.5 and 1.0. This test is useful when
scikit-learn cannot load because of missing or blocked native dependencies.

test_special_characters
~~~~~~~~~~~~~~~~~~~~~~~
Checks that technology names containing punctuation are recognized correctly:

    C++   -> c++
    C#    -> c#
    Node.js -> node.js

Manual runner
~~~~~~~~~~~~~
The block guarded by:

    if __name__ == "__main__":

stores all test functions in a list and runs them one at a time. It prints a
success or failure message for each test and collects failed test names. This
allows the file to run without pytest:

    py -3 test_matching.py

When pytest is installed, the same tests can be run with:

    py -3 -m pytest test_matching.py

The manual runner catches AssertionError separately from other exceptions, so
an incorrect expected result is reported differently from a runtime error.

GLOSSARY OF WORDS AND TERMS
---------------------------

TF-IDF
~~~~~~
TF-IDF means Term Frequency-Inverse Document Frequency. It gives a numerical
weight to each word in a document.

- Term Frequency measures how often a word appears in one document.
- Inverse Document Frequency reduces the importance of words that appear in
    many documents and gives more importance to distinctive words.

In this project, TF-IDF converts the resume and job description into numerical
vectors so their text content can be compared. Common words receive less
influence, while useful terms receive more influence.

Vector
~~~~~~
A vector is a list of numbers representing something. Here, a vector represents
a document's words and their TF-IDF weights. The resume becomes one vector and
the job description becomes another vector.

Cosine similarity
~~~~~~~~~~~~~~~~~
Cosine similarity measures how similar two vectors are by comparing the angle
between them. It normally returns a value from 0 to 1 in this project:

        0 means no meaningful similarity
        1 means the vectors point in the same direction

The matching engine multiplies this value by 100 to display a percentage.

Token
~~~~~
A token is a piece of text identified for processing, usually a word or a
technology name. For example, the text "Python and Docker" produces tokens
such as "python" and "docker" after cleanup.

Tokenization
~~~~~~~~~~~~
Tokenization is the process of splitting text into tokens. The _tokens helper
lowercases text, finds words and technology names with a regular expression,
and removes stop words.

Stop word
~~~~~~~~~
A stop word is a common word that usually adds little value to matching, such
as "the", "and", "to", or "with". The engine removes its small stop-word list
before keyword comparison and fallback cosine comparison.

Keyword
~~~~~~~
A keyword is a meaningful word or term used in a document. keyword_match
compares the unique keywords in the job description with the unique keywords in
the resume.

Keyword overlap
~~~~~~~~~~~~~~~
Keyword overlap is the number of job-description keywords also found in the
resume. The score is directional: it measures how much of the job's vocabulary
the resume contains.

Skill vocabulary
~~~~~~~~~~~~~~~~
The skill vocabulary is the SKILLS set in skills_database.py. It is the list of
known technologies, tools, languages, methods, and concepts that the engine can
recognize.

Canonical skill
~~~~~~~~~~~~~~~
A canonical skill is the standard name stored in SKILLS. For example,
"javascript" and "node.js" are canonical names used for consistent comparison.

Alias
~~~~~
An alias is another name or abbreviation for a skill. SKILL_ALIASES converts
aliases into canonical names. For example, "ReactJS" becomes "react", "K8s"
becomes "kubernetes", and "ML" becomes "machine learning".

Normalization
~~~~~~~~~~~~~
Normalization makes different spellings easier to compare. The engine converts
text to lowercase, cleans punctuation where appropriate, and maps aliases to
canonical skill names.

Regular expression (regex)
~~~~~~~~~~~~~~~~~~~~~~~~~~
A regular expression is a pattern used to find text. This project uses regex
patterns to find tokens and to detect complete skill names without accidentally
matching part of a larger word.

Boundary check
~~~~~~~~~~~~~~
A boundary check makes sure a match starts and ends at an appropriate word
boundary. It helps prevent a short skill such as "java" from being incorrectly
found inside "javascript".

Set
~~~
A set is a collection containing unique values. The engine uses sets so that a
skill or keyword repeated many times is counted once during overlap scoring.

Intersection
~~~~~~~~~~~~
The intersection of two sets contains values present in both sets. In the
engine, the intersection represents keywords or skills shared by the resume and
job description.

Score
~~~~~
A score is the numerical result of a comparison. Component scores and the final
match score are expressed as percentages from 0 to 100.

Weighted score
~~~~~~~~~~~~~
A weighted score gives different levels of importance to different components.
This engine gives keyword matching 40%, skill matching 40%, and TF-IDF text
similarity 20% of the final result.

Fallback
~~~~~~~~
A fallback is an alternative implementation used when the preferred method is
unavailable. If scikit-learn cannot load or calculate TF-IDF, the engine uses
the standard-library _token_cosine function instead of failing completely.

Cosine fallback
~~~~~~~~~~~~~~~
The cosine fallback counts token frequency with Counter and calculates cosine
similarity using math.sqrt. It is simpler than full TF-IDF because it uses word
counts rather than TF-IDF weights, but it maintains the same 0-to-100 output
contract.

Dependency
~~~~~~~~~~
A dependency is an external package or library that code relies on. This
project lists NumPy, SciPy, scikit-learn, pandas, and matplotlib in
requirements.txt. The preferred TF-IDF implementation depends on scikit-learn.

Lazy import
~~~~~~~~~~~
A lazy import loads a dependency only when a function needs it. tfidf_match
imports scikit-learn inside the function so keyword matching and skill
extraction can still work if scikit-learn is unavailable.

Exception
~~~~~~~~~
An exception is an error signal raised while a program is running. tfidf_match
catches selected exceptions from the optional scikit-learn path and switches to
the fallback implementation.

API
~~~
API means Application Programming Interface. It is the set of functions and
expected inputs and outputs that other code can use. The main matching API is
calculate_match(resume_text, job_description).

Input and output
~~~~~~~~~~~~~~~~
An input is data supplied to a function. An output is the value returned by the
function. The matching engine accepts resume and job-description strings and
returns numeric percentage scores or a set of extracted skills.

Edge case
~~~~~~~~~
An edge case is an unusual but valid input that should be handled safely. This
project tests empty strings and None values. They are treated as empty text and
return a score of 0.0.

Dependency-free
~~~~~~~~~~~~~~~
Dependency-free means that a code path uses only Python's standard library and
does not require third-party packages. The fallback cosine implementation is
dependency-free.

Pytest
~~~~~~
Pytest is a Python testing framework. It discovers functions whose names start
with test_ and runs their assertions. test_matching.py is written so it can be
run with pytest or directly with Python.

Assertion
~~~~~~~~~
An assertion is a condition that must be true for a test to pass. For example,
the tests assert that an identical resume and job receive a score of at least
90 and that empty inputs return 0.0.

Bytecode
~~~~~~~~
Bytecode is an intermediate form of Python code created for faster execution.
The __pycache__ folder contains generated .pyc bytecode files. These are
runtime artifacts and not the original source files.

Container
~~~~~~~~~
A container is an isolated environment used to package and run software. The
Dockerfile builds a Python container, installs the listed dependencies, copies
the ML files into it, and starts train.py.

Dockerfile
~~~~~~~~~~
A Dockerfile is a set of instructions for building a Docker container image.
The current Dockerfile uses Python 3.12 slim and launches the currently empty
train.py file.

Training pipeline
~~~~~~~~~~~~~~~~~
A training pipeline prepares data, trains a machine-learning model, evaluates
it, and saves the resulting model. This project does not yet have an active
training pipeline because train.py, data folders, and models are currently
empty.
